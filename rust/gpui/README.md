# {{ project-name }}

A GPUI desktop application template using `gpui-kit`, with an optional WebAssembly build.

## Features

- **GUI Framework**: [gpui-kit](https://github.com/longbridge/gpui-kit) (GPUI) with component library and asset support
- **Workspace**: Multi-crate workspace (`{{ project-name }}-ui`, `{{ project-name }}-app`, `{{ project-name }}-web`)
- **WebAssembly**: The same views run in a browser through the `gpui-kit` web backend
- **i18n**: [rust-i18n](https://github.com/longbridge/rust-i18n) with `zh-CN` / `en` locales
- **Logging**: `tracing` (stdout in debug, rolling files in release)
- **Single Instance**: `single-application` with unique instance ID (UUID generated by cargo-generate)

## Web (WebAssembly)

GPUI Kit's web target is `wasm32-unknown-unknown`, so the desktop `main` function is
replaced by the `run` export in `{{ project-name }}-web`. [Trunk](https://trunkrs.dev)
compiles the crate, runs `wasm-bindgen`, serves the page with auto-reload and writes the
static bundle — no Node.js, npm or shell scripts required.

```bash
cargo install trunk --locked

cd {{ project-name }}-web
trunk serve                # dev server with auto-reload, http://127.0.0.1:3000
trunk build --release      # static bundle in dist/
```

`dist/` can be served by any static host.

Notes:

- Run the commands inside `{{ project-name }}-web`: the crate pins the `nightly` toolchain
  (GPUI's web dependencies use the unstable `stdarch_wasm_atomic_wait`) and the
  `wasm32-unknown-unknown` target via `rust-toolchain.toml`; rustup installs both on the
  first build.
- `[tools] wasm_bindgen` in `Trunk.toml` must match the `wasm-bindgen` version in
  `Cargo.lock`, otherwise Trunk aborts with a version-mismatch error.
- `index.html` declares `data-trunk rel="rust"` for this crate, and
  `data-wasm-opt="0"` keeps `wasm-opt` out of the toolchain (change it to `"z"` to shrink
  the release bundle; Trunk then downloads `wasm-opt` automatically).
- `data-target-name="app_web"` selects the `cdylib` library target of the crate.
- Web support is currently **showcase-level** in GPUI Kit; verify input, accessibility,
  startup cost and deployment for your own product.
- The web platform has no system font database. `IBMPlexSans-Regular.ttf` is embedded
  (SIL Open Font License, see `fonts/LICENSE.txt`) and serves as both the UI font and
  the `.SystemUIFont` alias. Other glyphs fall back to the browser's Canvas.
- GPUI Kit's default icon set is not downloadable on the web. The template embeds the
  icons its components use with `gpui_kit::assets::icon_assets!` (see
  `{{ project-name }}-ui/src/lib.rs`); add icon names to that list when you introduce
  components that need more, otherwise those icons simply render empty.
- The web runtime supports a single top-level window; render dialogs inside `Root`.
